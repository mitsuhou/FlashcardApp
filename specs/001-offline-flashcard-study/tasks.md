# Tasks: Offline flashcard study and scheduled review

**Release scope.** All four P1 stories on one Android installation. Use the [clarified specification](spec.md), [plan](plan.md), [data model](data-model.md), [research decisions](research.md), [validation guide](quickstart.md) and [constitution](../../.specify/memory/constitution.md). The [readiness checklist](checklists/mvp-readiness.md) records requirements review. Runtime evidence comes from the tasks below.

Paths are relative to the repository root. Complete phases in order. Within each phase follow task IDs, except for the independent work marked `[P]` and described under Dependencies. Write story acceptance tests against each story’s specified starting data, then run them through the real entry points at the phase checkpoint.

## Dependencies and execution order

Setup → shared data foundation → US4 → US3 → US2 → US1 → integrated release. Use week 1 for setup, storage, profiles and the start of library editing. Finish the library early in week 2, then complete both study modes. Reserve week 3 for integrated validation, corrections and course presentation.

- In setup, T003 and T004 can proceed together once the baseline is established. In foundations, T006–T008 can proceed independently. Build the DAO pair T011/T012 after entity definitions, agree their shared eligibility predicate, then export the schema. T020–T023 use separate test files and private test stores after repository wiring.
- US4 can draft T024 and T025 together against the approved profile behavior. US3 can draft T030 and T031 together against seeded owned content.
- US2 can draft T038 and T039 together against the read-only projection. US1 can draft T042 and T043 together against the grading repository and UI contract. Integrate shared navigation and factory files in task order.
- Run each story’s tests at its checkpoint. A story is independently demonstrable using its stated fixture. The MVP release requires **all four**.
